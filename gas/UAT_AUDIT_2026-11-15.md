# UAT Audit — User-Supplied Google Apps Script Snapshot

Date: 2026-11-15  
Scope: static and isolated runtime review of the Apps Script text supplied in chat, compared with the maintained `main` branch backend.

## Executive result

**The supplied GAS snapshot is not the same as the maintained backend in `main`. Do not deploy this supplied snapshot as the production release.** It parses successfully and several operational authorization rules pass isolated checks, but the snapshot is missing critical fixes that already exist in the maintained repository.

The supplied file identifies itself as C-1E-B, contains 4,774 lines / 204,225 characters, and exposes a weaker backup-readiness check than the maintained backend.

## Findings in the supplied snapshot

| Severity | Finding | Evidence / impact |
|---|---|---|
| Critical | Backup comparison checks only sheet dimensions and headers | A copied Spreadsheet can contain altered or missing cell values while still being accepted as an equivalent backup. |
| Critical | Readiness does not require a recent successful Drive backup | The API can return `ready` without proving the configured backup folder, daily trigger, or recent successful backup file is usable. |
| High | Closing a Hazard-origin PICA does not update its linked Hazard | PICA can become CLOSED while its originating Hazard remains active. |
| High | Contractor report retries are not idempotent | A lost create/review response can cause a replay to return 409 even though the first request committed. |
| High | Multi-role Employee + Company Admin is evaluated as Employee | The route gate blocks the account, and `applyRecordScope_` uses the first role rather than resolving Company Admin privilege. This was reproduced in an isolated runtime harness. |

These are code-level checks only. They do not establish live Apps Script authorization, Spreadsheet access, Drive permissions, or real offline replay.

## Maintained backend changes

The maintained `gas/Code.gs` in `main` includes the missing protections:

- Full cell-by-cell backup snapshot comparison in chunks.
- Readiness requires accessible backup folder, installed daily trigger, and a recent successful backup file verified in the configured folder.
- Atomic PICA + linked Hazard update with rollback if the paired write fails.
- Idempotent create/review/resubmit handling for Contractor monthly compliance reports.
- Multi-role Employee restrictions now defer to Admin CGG / Company Admin privileges while preserving tenant scope.
- Backend release identifier aligned to C-1E-D.

Regression tests cover these cases in `gas/tests/`.

## Live UAT still blocked by deployment state

No live integration result can be recorded until the maintained GAS source is pasted into the actual Apps Script project, authorized, and deployed as a new Web App version. The following require real Google services and cannot be simulated by GitHub Actions:

1. Actual Spreadsheet ID and sheet/header validation.
2. Actual Script Properties and OAuth configuration.
3. Drive folder ownership/permissions and photo upload.
4. Trigger installation and a real backup file in Drive.
5. `/api/health/ready` returning `ready`.
6. Real multi-account tenant isolation across CGG, SLS, KIJA, VIP, BCJ, CHN, PAR, and ARL.
7. Real offline queue replay, lost-response retry, and two-device conflict handling.
8. Non-destructive recovery-copy verification.

## Required deployment sequence

1. Use the maintained file: [`gas/Code.gs`](./Code.gs) from the current `main` branch — not the supplied C-1E-B snapshot.
2. Update Script Properties and confirm the target Spreadsheet and Drive folders.
3. Run `setup()` only after confirming the target Spreadsheet is the intended HDOS database; do not run destructive cleanup functions.
4. Run `authorizeRepositoryDriveAccess()` if Repository Drive authorization has not been granted.
5. Run `createDatabaseBackup()` and verify a SUCCESS row and readable Google Sheets file in the configured backup folder.
6. Run `installDailyDatabaseBackupTrigger()`.
7. Deploy a new Apps Script Web App version.
8. Verify `/api/health/ready` returns `ready` and every readiness check is true.
9. Execute `PRODUCTION_UAT_CHECKLIST.md` with test accounts and evidence before production approval.

**Never change `HDOS_SPREADSHEET_ID` to a recovery copy during UAT.** Recovery cutover requires a separately approved maintenance window and rollback plan.
